# API Overview

The FinSarthi backend exposes its endpoints via FastAPI. An interactive Swagger UI is generated automatically and is available at `GET /docs` when running the application.

Below is a conceptual overview of the key endpoint groups and example workflows.

## Key Endpoint Groups

### Authentication (`/api/auth`)
Handles user identity and sessions.
- `POST /api/auth/register` - Create a new user.
- `POST /api/auth/login` - Authenticate a user and receive a JWT access token.
- `GET /api/auth/me` - Retrieve the currently authenticated user's profile.

### Core Finances (`/api/transactions`, `/api/budgets`, `/api/goals`)
CRUD operations for the fundamental financial entities.
- `GET /api/transactions` - List recent transactions with filtering/pagination.
- `POST /api/transactions` - Add a new transaction (auto-validates against budget limits).
- `GET /api/budgets/status` - View budget consumption metrics for the current period.

### AI Insights (`/api/insights`)
Exposes the analytical endpoints.
- `GET /api/insights/forecast` - Get a forward-looking cashflow forecast with natural language explanation generated by the LLM proxy.
- `GET /api/insights/fraud-check` - Ask the Guardian agent to validate a suspicious merchant or transaction string.

### Onboarding & Sync (`/api/sync`)
Handles importing offline data.
- `POST /api/sync/csv-preview` - Upload a CSV of bank statements to receive a parsed, validated preview.
- `POST /api/sync/csv-commit` - Confirm the preview to persist the parsed transactions into the database (includes deduplication).

### Admin & Exports (`/api/admin`, `/api/exports`)
Endpoints restricted to users with the `admin` role.
- `GET /api/admin/audit` - View system-wide security and mutation logs.
- `GET /api/exports/transactions` - Download a `.csv` export of transactions based on filter parameters.

### Demo (`/api/demo`)
Endpoints designed for presentation use.
- `POST /api/demo/reset` - Wipes the authenticated user's data and reseeds a full demo environment containing past transactions, active budgets, and generated insights. *Requires `DEMO_MODE_ENABLED=true` in environment configuration.*

## Example Flow: Generating an Insight

1. The client sends a `POST /api/auth/login` to get an `access_token`.
2. The client attaches the token (`Authorization: Bearer <token>`) and queries `GET /api/insights/forecast`.
3. The server computes deterministic past averages for income/expenses.
4. The server calls the AI provider (e.g. OpenAI via `LLM_PROVIDER`) to convert the deterministic numbers into a natural language summary.
5. If the AI provider is down, the server seamlessly catches the timeout and responds with a templated heuristic string.
6. The client receives the JSON payload: `{"forecast_amount": 1250.00, "explanation": "Based on the last 3 months, you are projected to save..."}`.
